# Glossary

!!! abstract "In this page"
    - Every internal term used on this site, in alphabetical order, with a plain meaning.
    - The "Also called" column gives code names and older names. Two matter most: **ClosedLoop** is the planner key `sage_plain`, and **AssistLoop** is the planner key `sage`.
    - Each term has an anchor, so you can link to it as `glossary.md#<id>`.

All paths in the "Also called" column are in the `robot_agent` repo at the checked commit, unless a repo is named. The last column links to the page on this site that explains the term.

| Term | Plain meaning | Also called | Where it is explained |
|---|---|---|---|
| <a id="action"></a>action (abstract action) | A step verb that does not depend on a robot, such as `MoveTo`, `Find`, `Pick`, `Place`, `PutIn`, `Open`, `Close`. A planner writes plans with these verbs. A robot package binds each one to a skill. | plan action; `ROBOT_ACTIONS` in `embodiplan/base.py` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="action-model"></a>action model | The one set of rules that says what each action needs before it runs and what it changes after. The gate, the guard, the symbolic verify layer and the belief updates all use it, so they cannot disagree. | `embodiplan.action_model`; `core/planning/action_model.py` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="action-model-version"></a>ACTION_MODEL_VERSION | The version string of the action model, `"1.0"`. `robot_agent` and `embodiplan` must report the same value; a test compares them. | `embodiplan/action_model.py` | [Planner library contract](../contracts/planner-library.md) |
| <a id="robotadapter"></a><a id="adapter"></a>adapter (RobotAdapter) | The one object a robot package gives the core. It binds plan steps to skills, observes the robot, reconciles the belief with sensors and reports sensor health. | `RobotAdapter` in `contract/adapter.py`; `configs/adapter.py` in a robot package | [Robot package contract](../contracts/robot-package.md) |
| <a id="announcer"></a>announcer | The part that turns plan progress into short spoken or shown phrases in the robot's language. | `core/planning/announcer.py` | [Dialog and intent](../concepts/dialog-and-intent.md) |
| <a id="assistloop"></a>AssistLoop | The loop that wraps a planner with understanding of the command, questions to the person, the certified gate before motion, and a guard before each step. It is the ClosedLoop plus these extras. | planner key `sage`; class `AssistLoop` in `core/planning/assist_loop.py`; "SAGE-v2" in older notes | [Closed loop](../concepts/closed-loop.md) |
| <a id="belief"></a>belief | What the robot assumes is true about the world: where it is, what it holds, which containers are open. It changes only when a skill succeeded and its checks passed, and it can be corrected from sensors. | `WorldState` in `core/planning/base.py` | [Belief and reconcile](../concepts/belief-and-reconcile.md) |
| <a id="bind"></a>bind (binding) | Turning an abstract step into a skill name and its parameters for this robot. If the robot cannot do the step, the adapter raises `Unbindable`. | `RobotAdapter.bind`, `Unbindable` in `contract/adapter.py` | [Robot package contract](../contracts/robot-package.md) |
| <a id="bring-ask"></a>bring_ask | An option, on by default. A request to bring something to the speaker ("bring me the mug") asks one combined question, "Where are you? Or where should I put it?", also when the robot tracks the person. Asked once per request; not asked for a hand-over request ("hand me the mug"). Switch off with the run option `bring_ask=0`. Checked with English phrases only; Korean and Vietnamese are not verified. | `robot_agent/options/bring_ask.py`; `$ROBOT_AGENT_BRING_ASK`; pack phrase `q_where_bring` | [Dialog and intent](../concepts/dialog-and-intent.md#two-questions-the-robot-adds-before-it-plans) |
| <a id="budget"></a>budget (LLM-call budget) | The most LLM calls one run may make. The default is 20; `0` means no limit. A run that uses it up ends as failed with the code `budget_exceeded`. | `llm_budget`, `ROBOT_AGENT_LLM_BUDGET`; `core/planning/budget.py` | [Closed loop](../concepts/closed-loop.md) |
| <a id="bt-goal"></a>bt_goal (and `mixed`) | An option, on by default. A goal kind can be run by a small behaviour tree that the robot declares as data (`trees`), instead of a SAGE plan. A robot that declares no `trees`: nothing happens. Key `mixed` (default on): goals with a tree run as trees; neighbouring goals without a tree are planned by SAGE once, when the run reaches them; each of their steps goes through the loop's own step path and recovery; a step with no way left hands the goals still open to the SAGE replan. Not covered: the certify gate is skipped for those SAGE parts. Its effect on a benchmark is not measured. Switch off: `bt_goal=0`; only the mixing: `bt_goal.mixed=0`. | `robot_agent/options/bt_goal.py`; `core/planning/behavior_tree.py`; `docs/bt_goal.md` | [Closed loop](../concepts/closed-loop.md#options-that-change-the-flow) |
| <a id="gate"></a><a id="certified-gate"></a>certified gate | A check of the whole plan on the belief before the robot moves. Critical findings go back to the planner for repair. A plan that still has critical findings never runs. | gate; `AssistLoop._check` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="clarify"></a>clarify | The robot asks the person a question before it plans, when the command is unclear. It is sent to the dashboard as the `clarify` event. | `Clarify` in `api/events.py` | [Dialog and intent](../concepts/dialog-and-intent.md) |
| <a id="closedloop"></a>ClosedLoop | The plain loop around any planner: plan, act on one step, check the result, replan after a failure. | planner key `sage_plain` (as a run's planner choice); class `ClosedLoop` in `core/planning/loop.py` | [Closed loop](../concepts/closed-loop.md) |
| <a id="codec"></a>codec | A named function that encodes or decodes a device message. A connection names it as `codec:<name>`. Inline code strings in a connection file still work but are deprecated. | `encode_func`, `decode_func`; `connect/codecs.py` | [Robot and simulators contract](../contracts/robot-and-simulators.md) |
| <a id="connections-json"></a>connections.json | The list of device connections for one site: ROS topics, actions and services, TCP links and LLM servers. | devices; per site under the robot package's `configs/locations/` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="device-agent"></a>device agent | One named connection inside the ROS node. A skill reaches it as `node.agents['<name>']` and calls `.get()` or `.send()`. | `NodeAgent` in `connect/ros/node.py` | [Robot and simulators contract](../contracts/robot-and-simulators.md) |
| <a id="direct-planner"></a>direct planner | A planner that makes one LLM call and gets a program of `skill::inputs` lines. It does not replan. | planner choice `direct`, key `llm_direct`; `backends/llm_direct.py` | [Planners](../concepts/planners.md) |
| <a id="domain"></a>domain (domain pack) | In `symbolic_robot`: one type of simulated world, such as `home` or `factory`, with its own skills, profiles and a robot package for `robot_agent`. | `domains/<name>/` | [symbolic_robot](../repos/symbolic-robot.md) |
| <a id="embodiplan"></a>embodiplan | The planner library that `robot_agent` uses. It holds the SAGE planner, baseline planners and the action model. | `embodiplan` package | [embodiplan](../repos/embodiplan.md) |
| <a id="env"></a>ENV | The site's table of named places, with keys such as `table@living room`, coordinates and aliases. Planners and the belief use these names. | places; `ENV` in `skill_configs.py` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="episode"></a>episode (VLA) | One recorded teleoperation sequence, kept as raw files, used to train a VLA policy. The core only reads them and keeps an edit list next to them. | raw episode; `core/episodes.py` | [Runs and records](../concepts/runs-and-records.md) |
| <a id="failure-code"></a><a id="failurecode"></a>FailureCode | The reason a skill failed, one of 13 codes shared by every robot, such as `absent`, `unreachable`, `grasp_failed`, `timeout`, `budget_exceeded`. | `FailureCode` in `contract/types.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="fetch-guard"></a>fetch_guard | An option, on by default. The place an object must end up is never taken for the place where it is now. Three parts: an `on` / `in` goal with no source and no trusted sighting gets a first place from the ranked search (never its destination) before planning (`rank_unknown`); a plan that Finds or Picks that object at its own destination gets a gate finding, so the repair asks for another plan (`plan_finding`); a failed `Find` with code `unknown` and no reason text becomes `absent`, so the search ladder and then "I couldn't find the X. Where is it?" run instead of replanning the same plan (`absent_find`). Switch off: `fetch_guard=0`; one part: `fetch_guard.rank_unknown=0` and so on. Not measured on any benchmark; not run with a real LLM. | `robot_agent/options/fetch_guard.py`; `$ROBOT_AGENT_FETCH_GUARD`; lab flag `fetch_guard` | [Debug a failed run](../guides/debug-a-failed-run.md#the-fetch_guard-flag) |
| <a id="goal"></a>goal (typed goal) | What the person wants, as a small record with a kind: `on`, `in`, `open`, `close`, `go`, `say` or `deliver` (and an optional `give`, off by default). | `GOAL_KINDS`, `OPTIONAL_KINDS` in `core/planning/goals.py` | [Dialog and intent](../concepts/dialog-and-intent.md) |
| <a id="goal-check"></a>goal check | A look at the world after the plan to see that the goals hold. The run counts as done only when they are seen to hold. The default mode is `observe`. | `goal_check` option and event; `AssistLoop._observe_goals` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="grace"></a>GRACE | The old name of the SAGE planner. The old names still work, deprecated: the registry and request name `grace` (it resolves to `sage`, and as a request to `sage_plain`), the robot module `grace_namemap` (read when there is no `sage_namemap`), the memory store `grace_memory` (copied once to `sage_memory`) and the install extra `.[grace]` (an alias of `.[sage]`). | `core/planning/planner_names.py`; `contract/legacy_adapter.py`; `observe/paths.py`; `pyproject.toml` | [Planners](../concepts/planners.md) |
| <a id="sage-namemap"></a>sage_namemap | A per-robot module `configs/sage_namemap.py` with name maps and parameter builders. `NamemapAdapter` wraps it so it works as a RobotAdapter. A robot with `configs/adapter.py` does not need it. | `contract/legacy_adapter.py` | [Robot package contract](../contracts/robot-package.md) |
| <a id="guard"></a>guard (per-step guard) | A check of one step's preconditions on the current belief, right before the step runs. It catches changes since the plan was made. | `AssistLoop._guard`; `docs/guard.md` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="health"></a>health (sensor health) | The adapter's report on its sensors: camera frame age, frame rate, depth, pose age. Stale sensors stop the loop from trusting a look or an arrival. | `RobotAdapter.health`; `core/planning/sensor_health.py` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="intent"></a>intent | What someone's words mean while a run is active: `stop`, `pause`, `resume`, `modify`, `add`, `drop`, `new`, `status` or `answer`. | `Intent` in `interact/intent_router.py` | [Dialog and intent](../concepts/dialog-and-intent.md) |
| <a id="interruptible"></a>interruptible | A skill setting. `true` means the skill may be stopped in the middle. `false` means it must finish or release safely first, for example while holding something. | `SkillSpec.interruptible` in `contract/types.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="look-then-ask"></a>look_then_ask | An option, on by default. For an `on` or `in` goal whose source the request does not name and the memory does not trust, the robot looks where it stands with one `Find`. Seen: that place is the source. Not seen: it asks once, "I don't see the X here. Where is it?". "I don't know" or no place in the answer leaves the goal to the ranked search by belief. Switch off with the run option `look_then_ask=0`. Checked with English phrases only; Korean and Vietnamese are not verified. | `robot_agent/options/look_then_ask.py`; `$ROBOT_AGENT_LOOK_THEN_ASK`; pack phrase `q_where_is_here` | [Dialog and intent](../concepts/dialog-and-intent.md#two-questions-the-robot-adds-before-it-plans) |
| <a id="manifest"></a>manifest | The robot's `configs/manifest.yaml`. It declares skills, capabilities, geometry, languages and optional planner notes and seed memory, as data. | `Manifest` in `contract/manifest.py` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="memory"></a>memory (seed and live) | Example plans a planner can copy from. Seed memory is shipped by the robot package. Live memory is learned from past runs; by default only runs whose goals were seen to hold are kept. | `planner.seed_memory` in the manifest; `core/planning/episode_memory.py`; `docs/memory.md` | [Planners](../concepts/planners.md) |
| <a id="offer-near"></a>offer_near | A key of `look_then_ask`, on by default. When the answer to "I don't see the X here. Where is it?" names no place or room (a typo, an unknown name, a bare word that matches several places), the robot asks ONE follow-up that offers up to 3 near places, never the goal's destination: "I could not find '...' on my map. Do you mean: ...? Or tell me another place." Still no place: no third question. The text exists in English only. Switch off: `look_then_ask.offer_near=0`. Not measured; not run with a real LLM. | `robot_agent/options/look_then_ask.py`; pack phrase `q_place_unknown`; lab fields `answered_unmatched`, `second_answer` | [Dialog and intent](../concepts/dialog-and-intent.md#two-questions-the-robot-adds-before-it-plans) |
| <a id="open-loop"></a>open-loop path | The older path: one LLM plan, then the steps run without replanning. | `UnifiedAgent.run` in `core/unified_agent.py` | [Planners](../concepts/planners.md) |
| <a id="option"></a>option (engine option) | One switchable behaviour of the AssistLoop, written as a module that declares its keys and hooks to the engine. Its key is read from a run option, then the environment, then the manifest. `python -m robot_agent.core.options list` prints them. | `robot_agent/options/<name>.py`; `core/options/`; `docs/options.md` | [Closed loop](../concepts/closed-loop.md#options-that-change-the-flow) |
| <a id="plan-skill"></a>plan skill | A skill defined as a plan of other skills, stored as data with `type: plan` in `skills.json`. It runs like any other skill. | `core/plan_skill.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="plan-tidy"></a>plan tidy | Removal of steps that the action model proves do nothing, before the gate checks the plan. For example, `Find X` while X is already in the hand. No LLM call is used. | `core/planning/plan_tidy.py` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="planner"></a>planner | Any object that has the two methods of the `Planner` protocol (`base.py`). Both return `(steps, metrics)`; a step is a small dict such as `{"action": "Find", "object": "cup"}`. The core adds understanding, gating, recovery and recording around it. | `Planner` in `core/planning/base.py` | [Planners and loops](../concepts/planners.md) |
| <a id="presence"></a>presence | A small heartbeat file that tells which machines run the robot package now and on which site. It is used to warn when two machines share a site. | `presence.py` | [Run the system](run-the-system.md) |
| <a id="provenance"></a>provenance | For each belief field, where its value came from: `sensor` (with a time), `operator`, `belief` or `unknown`. | `WorldState.provenance` in `core/planning/base.py` | [Belief and reconcile](../concepts/belief-and-reconcile.md) |
| <a id="reconcile"></a>reconcile | Bringing the belief in line with the sensors, at the start of a run and on resume. A field the sensors cannot read stays a belief and is marked unconfirmed. An object kept as `found` from an earlier run is dropped when the base has moved more than 0.25 m from where it was seen (the report says `found_dropped`). | `core/planning/reconcile.py`; `RobotAdapter.reconcile` | [Belief and reconcile](../concepts/belief-and-reconcile.md) |
| <a id="recovery-policy"></a>recovery policy | A table that says what to do after each failure code: for example retry, look again, wait for sensor health, ask for help, replan or stop. A robot may override single entries. | `RecoveryPolicy`, `RecoveryRule` in `contract/recovery.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="replan"></a>replan | Asking the planner for a new rest of the plan after a failure. | `replan` in `core/planning/base.py` | [Closed loop](../concepts/closed-loop.md) |
| <a id="replay"></a>replay | Running a recorded run again offline. LLM calls are answered from the record, and `exec --fake` uses a fake robot that returns the recorded skill results. A prompt that differs raises an error. | `observe/replay.py` | [Runs and records](../concepts/runs-and-records.md) |
| <a id="robotview"></a>RobotView | The robot as the loops see it: the adapter plus lookups they share, such as the manifest, geometry, messages and the recovery policy. | `core/planning/robot.py` | [Robot package contract](../contracts/robot-package.md) |
| <a id="run"></a>run (run_id) | One execution of one command, with its own id. A robot has one active run at a time. Cancel, pause and resume apply to a run. | `Run`, `RunManager` in `interact/run_manager.py` | [Runs and records](../concepts/runs-and-records.md) |
| <a id="runrecord"></a>RunRecord | One JSONL file with everything a run did. Replay reads it. | `observe/record.py` | [Runs and records](../concepts/runs-and-records.md) |
| <a id="sage"></a>SAGE | "Symbolic Action-Gating and Editing", the planner in `embodiplan`. In `robot_agent`, the registry name `sage` is the planner (`SageBackend`), and the request name `sage` selects the AssistLoop around it; `sage_plain` selects the plain ClosedLoop around it. | `embodiplan/sage.py`; "SAGE-v2" in older notes | [Planners](../concepts/planners.md) |
| <a id="site"></a>site (location) | One place where a robot is deployed, with its own connections, overrides and map. | location; `api/locations.py` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="skill"></a>skill | A robot function that takes the ROS node and parameters and returns a result dictionary. It is registered as `internal`, `external` or `plan`. | `core/skill_registry.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="skillresult"></a>SkillResult | The normalised outcome of a skill: `ok`, `code`, `msg`, `device`, `data`. | `SkillResult` in `contract/types.py` | [Skills and failures](../concepts/skills-and-failures.md) |
| <a id="skillspec"></a>SkillSpec | One skill as the manifest declares it: name, action, parameters, preconditions, effects, verify layers, errors and whether it is interruptible. | `SkillSpec` in `contract/types.py` | [Robot as data](../concepts/robot-as-data.md) |
| <a id="spoken-names"></a>spoken names | A `said->real` pair in a plan. The robot says the left name; the skill receives the right one. | `spoken.py` | [Dialog and intent](../concepts/dialog-and-intent.md) |
| <a id="subgoal-repair"></a>SubgoalRepair | An optional planner capability: repair only the sub-goal block that has a critical finding, instead of making a new plan. | `core/planning/subgoal_repair.py` | [Planners](../concepts/planners.md) |
| <a id="symbolic-simulator"></a>symbolic simulator | A simulated robot whose skills do not move anything. Each skill checks preconditions on a small symbolic world, draws an outcome from declared probabilities and applies the effect. | symbolic mode; `symbolic_robot` repo | [symbolic_robot](../repos/symbolic-robot.md) |
| <a id="truth"></a>truth | In symbolic simulators, the record of what really happened in a call. The robot never sees it. | `Result.truth` in `symbolic_robot` | [symbolic_robot](../repos/symbolic-robot.md) |
| <a id="typed-refusal"></a>typed refusal | The robot refuses only for a typed reason (a `kind`), never because the model wrote something unfriendly. It ends the run as refused. | `typed_refusal` in `core/planning/understand.py` | [Dialog and intent](../concepts/dialog-and-intent.md#typed-refusals) |
| <a id="verify-layers"></a>verify layers | Checks after a skill reports success: `isdone` first, then `symbolic`, then optional `vlm`, and `sensor` or `localization`. The effects enter the belief only if they pass. | `StepVerifier` in `core/planning/verify.py`; `VerifySpec` | [Checks before motion](../concepts/checks-before-motion.md) |
| <a id="vla"></a>VLA | Vision-language-action policy. Here it is used to open drawers. It is trained and tested in the `kcare_sim` house and served by a separate service. | SmolVLA, `vla-serve` | [kcare_sim](../repos/kcare-sim.md) |
